# World import evidence

Issue #7 tracks the complete importer. The desktop and browser workspace read world archives, preserve their configuration facts, and reconstruct capacity goals for supported assigned machines. The Imported factory dialog lets the player correct recipe assignments and retained outputs. Unassigned and unsupported machines remain visible.

`kernel/world.js` reads ZIP directory entries individually, verifies their checksums, and decodes region chunks and big-endian NBT. It retains signed 64-bit NBT values as decimal strings. It recognizes wrapper directories, the vanilla dimensions, and namespaced dimension folders. Malformed chunks and block entities produce entries in the import report rather than deleting successfully read machines. Current limits are 256 MiB per archive entry, 32 MiB per expanded chunk, 128 NBT nesting levels, and two million NBT collection entries. ZIP64 directory records and extended entry fields are supported. Region chunks support gzip, zlib, raw NBT, and Minecraft’s Java LZ4 block stream. Split and encrypted archives remain unsupported.

The machine adapter reads `activeRecipe`, `upgradesItemStack`, `machinesStack`, `activeShape`, and `casing` from the matching MI and addon serialization. The contained machine determines an array's recipe type. Unrecognized mod block entities retain their coordinates and raw facts for later adapters or correction. These facts establish saved configuration, not measured throughput.

The replicator adapter reads its first `items` entry's resource key and amount. A nonempty default-stack template selects the corresponding verified replication route and records that the template has been obtained. It does not become a free input supply. Component-bearing templates without matching rules remain unresolved. The AE2 molecular assembler reads the dedicated pattern in `inv.item10`, speed cards from `upgrades`, and an active forced pattern from `myPlan` when present. Forced patterns retain a separate evidence label because they may be temporary network work. A dedicated pattern with substitutions disabled pins its actual ingredient choice. Conflicting fixed choices remain unresolved rather than silently combining incompatible targets.

The AE2 adapter follows version 19.2.17, source tag `neoforge/v19.2.17`, commit `79ee2c704ad62941a426c26b1cb1f76ef5b2ee5a`. `PatternProviderLogic`, `AppEngInternalInventory`, `CableBusContainer`, `EncodedProcessingPattern`, `EncodedCraftingPattern`, and `GenericStack` define the fields. Pattern inventories contain item stacks with `Slot` and encoded components. Cable parts are stored under direction names. Block providers use the block-state `push_direction` property. Processing patterns carry `sparseInputs` and `sparseOutputs`, with AE resource type `#t` and quantity `#`.

Patterns remain provider configuration. They do not create production machines. An unassigned adjacent machine receives an inferred recipe only when its recipe type and the pattern's material quantities match a single normalized or compiled process. Multiple matches remain ambiguous. Saved active recipes take precedence. Remote networks, multiblock hatch relationships, and additional machine serialization formats still need adapters and verification.

`kernel/reconstruct.js` compiles saved loadouts with the same capacity rules as ordinary goals. It groups identical configurations while retaining each origin. Its initial inference keeps primary outputs with no other assigned consumer as capacity goals. Material links are deductions, not a recovered cable network. Cycles and byproduct retention can need corrections. Only retained end-goal configurations constrain the new request; an imported upstream bottleneck does not constrain the recalculated factory. Requester quantities stay separate.

With the portable catalog, the controlled world's macerator reconstructs one machine with eight advanced upgrades and a configured capacity of 40 copper dust per second. The three unassigned controllers remain unresolved. The browser application imported that real ZIP, preserved the goal, allowed its removal in the review dialog, and persisted the correction. The fixture controllers are unformed, so this establishes saved configuration and reconstruction, not a functioning multiblock installation.

The runtime probe identifies 52 multiblock-part types through the actual hatch class. The importer retains these parts separately from production machines. It also captures 60 machines' active-shape templates, including positions and allowed hatch types, for the upcoming controller-association adapter. Preview blocks alone do not prove a saved structure is formed.

ME Requester 1.21.1-1.5.0 stores indexed entries under `requests`. Each entry has a resource `key`, enabled `state`, stock `amount`, and crafting `batch`. The adapter follows tag `v1.21.1-neoforge-1.5.0`, commit `57554ba7e126b38e4a38f19c37cf9916dfef48bc`. It preserves long quantities as decimal strings and leaves their rate unset. Neither a stock threshold nor a crafting batch establishes a refill interval.

## Reproduce the controlled world check

Use the isolated instance described in [extraction evidence](extraction.md). Run the capture tool with `--fixture`, or apply `tools/extraction/fixture-commands.txt` after startup. The commands configure six machines at y=100. They do not form the multiblocks or measure production. The Java fixture command places both AE2 provider forms with a copper-cluster processing pattern, a separate input hatch, and an ME Requester configured for 4,096 copper dust with crafting batch 64. It also creates a replicator with one iron-ingot template and a molecular assembler with a dedicated oak-plank-to-stick pattern and two speed cards. It uses the mods' inventory and component APIs. Save and stop the server before archiving its world with `python tools/extraction/archive_fixture.py --world <world-directory> --output <world.zip>`.

Run `node tools/verify_world_capture.mjs <world.zip> <machines.json> <report.json>`. The fixture check requires the macerator's assigned recipe and eight advanced upgrades, an unassigned assembler, a singleblock array containing 16 macerators and four turbo upgrades, and a multiblock array containing eight distillation towers. It also checks both provider directions, the separate hatch, and the requester's exact quantities without an invented rate. Keep the world archive outside Git. The compact report records its digest and selected facts.

Run `node tools/verify_kernel_browser.mjs <world.zip> <machines.json>` to compare the actual archive's import in Node and a browser Worker inside a cross-origin iframe. This is an isolated computation test, not verification of an exported Godot application. Run `npm test` for synthetic NBT, ZIP, region, AE2, capacity, and planning regressions.

Pass the compiled player catalog in place of the raw machine capture to verify the extended six-machine fixture and reconstruct its three capacity goals. `node tools/verify_real_catalog.mjs <player-catalog.json> <world.zip>` checks 40 copper dust/s, 1 replicated iron ingot/s with 100 mB/s UU matter, and 80/6 sticks/s with 40/6 oak planks/s. These are independently derived configured capacities. `node tools/verify_app_browser.mjs <world.zip> <player-catalog.json> <player-catalog.json> extended` exercises the newer fixture in the exported application, including retained template and ingredient settings.

## Archive and compression checks

ZIP64 parsing follows the directory records and extended entry fields in the [PKWARE ZIP specification](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT). The controlled world was archived with 65,536 entries using Python’s ZIP writer and imported through the exported browser application. Reproduce that directory form with `archive_fixture.py --zip64-directory`. The added empty files exist only in the archive.

LZ4 parsing follows [lz4-java 1.8.0](https://github.com/lz4/lz4-java/tree/1.8.0), including its block headers and masked XXHash32 checksum. Set `region-file-compression=lz4` in the isolated server before saving the fixture. The verified archive contains 81 LZ4 chunks alongside 760 unchanged zlib chunks. Node, browser Worker, and exported Godot browser imports recovered all six configured machines. The exported application also passed plan persistence and editing checks. Small streams produced by the same Java library cover raw and compressed blocks; regression checks reject invalid offsets, checksums, truncation, and output beyond the import limit.
